01 / Keep the answer visible during recovery

Before / document review

Requirements and behavior

The overlay shows one exact-current hint. Complete-code requests show the answer spine before separately generated source. A source failure preserves the hint. Clarifications retain accepted question identity; stale source cannot replace a revised answer. Exhausted failures offer Retry hint for the exact current request.

Acceptance: Obsolete code never replaces a revised answer. Failure leaves the answer readable.

Review limitation: Validate live capture and end-to-end latency separately.

After / human review
The current answer stays visible while recovery and code generation report their own progress.
Keep accepted answer → Retry only the failed request → Attach current code

What must hold: Obsolete code never replaces a revised answer; Failure leaves the answer readable.

Still unverified: Validate live capture and end-to-end latency separately.

02 / Export only the intended record owner

Before / document review

Requirements and behavior

Sync validates the exact active chart-owner label before changing the store. Export with the same required owner applies an exact label filter unless an explicit owner filter is supplied. Empty filters do not disable that default. Shared stored records and incremental state remain owner-scoped.

Acceptance: Owner mismatch causes no store write. Empty filters do not broaden export scope.

Review limitation: Confirm behavior against a synthetic multi-owner fixture before any live use.

After / human review
Owner validation happens before writes, and export defaults remain scoped to that same owner.
Check active owner → Apply exact filter → Export scoped records

What must hold: Owner mismatch causes no store write; Empty filters do not broaden export scope.

Still unverified: Confirm behavior against a synthetic multi-owner fixture before any live use.

03 / Publish the feed only after audio is ready

Before / document review

Requirements and behavior

The pipeline collects sources, writes a source document and manifest, generates audio, uploads and verifies public URL/MIME/byte length, records audio identity, then atomically replaces RSS. Audio generation or verification failure does not change public RSS. Shadow mode stops before publication. Same-date reruns replace an existing GUID.

Acceptance: Audio failure leaves the public feed unchanged. Rerun replaces the episode instead of duplicating it.

Review limitation: Exercise a controlled upload failure before production acceptance.

After / human review
Audio is uploaded and verified before the public feed changes.
Build episode → Verify uploaded audio → Replace feed atomically

What must hold: Audio failure leaves the public feed unchanged; Rerun replaces the episode instead of duplicating it.

Still unverified: Exercise a controlled upload failure before production acceptance.
