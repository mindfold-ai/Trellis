# Prevent archive repository-map drift

## Goal

Ensure generated repository maps are refreshed or validated after Trellis task archive moves so PRs do not retain stale active-task paths.

## Background

A downstream recovery PR failed CI after Trellis task archive moves because a generated repository map still referenced paths under active task locations. Similar generated-scope issues appeared in PR body and housekeeping flows. This task tracks the detection or refresh behavior so archive moves do not leave stale generated maps behind.

## Requirements

- Identify the generator and validation owner for repository maps affected by Trellis task archive moves.
- Define whether Trellis lifecycle tooling, sd-ai-command-pack, or consumer repo checks should refresh generated maps after task archive moves.
- Detect stale active-task paths in generated maps before PR/CI where feasible.
- Preserve generated-file scope disclosure in PR bodies and review summaries.
- Avoid requiring Trellis core changes unless Trellis owns the map generation or archive-move trigger.

## Acceptance Criteria

- [ ] The owner of repository-map refresh or validation is documented.
- [ ] Archive-induced stale active-task paths are either refreshed automatically or reported before PR/CI failure.
- [ ] A regression test, fixture, or documented validation command covers task archive moves and generated map drift.
- [ ] PR/review generated-scope requirements remain explicit.
- [ ] Any external issue, PR, or task needed for sd-ai-command-pack or consumer-generated-doc ownership is linked from this task.
