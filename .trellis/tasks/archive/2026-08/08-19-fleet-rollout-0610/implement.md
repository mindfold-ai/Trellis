# Implementation — fleet rollout of Trellis >=0.6.10

## Per-consumer procedure

For each consumer, in cohort order:

1. Re-assert clean tree and default branch: `git -C <repo> status --porcelain`
   must be empty. Non-empty → skip that repo and report.
2. Record pre-state: `.trellis/.version`, and confirm the grep FAILS (proving
   the repo is genuinely affected and the upgrade is not a no-op).
3. `git -C <repo> checkout -b chore/trellis-0.6.14`
4. `trellis update --dry-run` from the repo root. Review the diff summary.
   Unexpected scope → stop, do not proceed to step 5.
5. `trellis update` for real.
6. Verify: `.trellis/.version` >= 0.6.10 AND the grep now PASSES.
7. Run the repo's `candidateChecks` from the manifest, if any.
8. Clear that repo's orphan session files, if any (loadsmith, rwbp-website,
   mezmo_benchmark only).
9. Commit on the branch. No push.

## Cohorts

- canary (sequential): rwbp-coordinator → loadsmith → hoa-manager
  **Stop after this cohort and report before continuing.**
- post-canary: rwbp-website → mezmo_benchmark → se-ai-command-pack → sd-github-review
- final: anomaly-metric-creator

## Validation commands

Per repo:
```
git -C <repo> status --porcelain          # empty before starting
grep -c '_context_path(repo_root, previous.context_key)' \
  <repo>/.trellis/scripts/common/active_task.py   # 0 before, >=1 after
cat <repo>/.trellis/.version                       # 0.6.7 before, 0.6.14 after
```

Fleet-wide at the end: re-run the scan that produced the PRD table; all 8 rows
must read 0.6.14 with the grep passing.

## Review gates

- After the canary cohort — mandatory stop, report, await go-ahead.
- Before any `git push` — not authorized by this task.

## Rollback

Per repo: `git checkout main && git branch -D chore/trellis-0.6.14`. Nothing is
pushed, so rollback is local and complete. Orphan session file deletions are the
one non-git-tracked action; those files are stale pointers to ended sessions and
are regenerated by normal use, so their loss is not a rollback concern.
